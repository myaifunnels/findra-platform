1. Purpose

This document locks the design of client-requested public-site changes that are already implemented on findra.ph. Use it for client sign-off, QA, and future Claude / designer work without re-deriving the brief.

Source of truth. Original comments came from the client Google Doc. Behavior below is what engineering shipped. Do not invent new UI from this spec.

1.1 Design principles from this round

  • Search and browse must respect the user’s category, keyword, and service — never dump the full directory.
  • There is no “Business Type”. Taxonomy is Category → Sub-category → Service.
  • The public site cannot create new top-level categories. Only the five main categories exist at that layer.
  • Filters get more specific as the user chooses; location is useless until the need is identified.
  • Listing content is capped so profile pages stay scannable and consistent.
  • Contact methods (WhatsApp, Viber, email, social) appear only when the business provided them.
  • Footer matches the old website: high-contrast white wordmark on green, brand socials, no account login.
  • Light and dark modes persist in localStorage (findra-theme).

2. Shared visual system

  • Brand green for primary CTAs, kickers, and the public footer band.
  • Header logos: light-mode logo on light chrome; client-provided dark-mode logo in dark theme.
  • Green footer wordmark: white, larger, high contrast — not the same color as the footer background (match old website).
  • Social icons: Facebook and Instagram only, brand-correct (not both pink). Links: Facebook findraph, Instagram findra.ph.
  • Contact: hello@findra.ph. Do not use info@findra.ph.
  • Listing editor workspace: desktop form-left / live-preview-right; mobile Edit details / Live preview toggle.
  • Progress bars: high-contrast tracks in both themes.

2.1 Five main categories (immutable on the public site)

  1. Products & Suppliers
  2. Services & Rentals
  3. Professionals
  4. Freelancers & Creatives
  5. Community & Institutions

Featured listing cards may only show one of these as the category under the tagline. Sub-categories (e.g. Event Coordination, Venues & Rentals) live under a main category and are not new top-level tiles.

3. Home

3.1 Keyword search

Client request — not suggestive; always goes to businesses

  • Single field, placeholder Keyword, magnifying-glass prefix.
  • No typeahead / listing suggestions while typing.
  • Enter or Search submits to /listings.
  • If keyword present, query includes search=.
  • If a category is chosen, query also includes category=.

3.2 Business Category dropdown

Client request — chosen category must filter, not show all

  • Default option: “Business Category” (empty value).
  • Options: the five main categories only.
  • Search lands on Businesses already filtered to that category.

3.3 Category tiles

  • Five cards: image, name, short description, See More.
  • See More goes to /listings?category=<Name> and must show only that category.

3.4 Featured Businesses

  • Grid / List toggle; View all → /listings.
  • Category under the tagline is a main category only.
  • Description preview: left-aligned, 2-line clamp, truncated to 120 characters at a word boundary with an ellipsis (LISTING_SUMMARY_CHAR_LIMIT).

3.5 Be Discovered

Heading: Be Discovered. Body with the client line break:

When visibility means growth,
we make sure your business gets noticed by the people who matter.

CTA: Showcase Your Business → /packages.

4. Businesses (/listings)

4.1 Breadcrumb

Home → Businesses — never “Search Results”.

4.2 When results appear

Do not show matching businesses while Category and Sub-category are both All and there is no keyword or service query. Location alone is not enough.

A “selection” is active when any of these is true:

  • Business Category ≠ All
  • Sub-Category ≠ All
  • Keyword is non-empty
  • Find a Service query is non-empty

Idle copy: “Pick a category, sub-category, service, or keyword above to find matching businesses.” Mobile chip: “Filter to see results”. Count “N matching businesses” only when a selection is active.

4.3 Filter rail (top to bottom)

ControlBehavior
Keyword (page heading search)Filters name, title, category, services, description, location
Business CategoryAll + five main categories. Removes Business Type entirely.
Sub-CategoryDirectly under Category. Options from published listings in the selected category. Disabled if none.
Find a ServiceRenamed from Business Services. Text field, placeholder “Search”. Filters the result list. No bullet/chip picker under the field.
LocationGoogle address input. Disabled until a selection exists. Hint: “Choose a category, sub-category, or service first to search by location.” Matches the city/area token against listing location — not every listing regardless of place.

4.4 Results chrome

Grid and map view toggle remain. Location active state shows “Searching near {place}” with Clear.

5. Business profile (/listing/:id)

5.1 Identity meta

  • No Business Type field.
  • Label is Category: (not “Business Category”).
  • Value format: Main category / Sub-category, Sub-category.
  • Client example: Category: Services & Rentals / Event Coordination, Venues & Rentals.
  • Then Business Address.
  • Then Operating Hours only if the listing has hours.

5.3 Media guidance (editor hints)

  • Logo: square JPG/PNG/WebP, up to 12 MB, 500×500 or larger.
  • Featured image: landscape JPG/PNG/WebP, up to 12 MB, 1200×630 or larger.
  • Gallery: JPG/PNG/WebP/GIF, up to 12 MB each, max 6.
  • Featured video: public YouTube URL or one MP4 (H.264, up to 50 MB, 720p recommended). Player must show preview + play, not YouTube-only.
  • Attachment: PDF, JPG, or PNG, up to 12 MB. Suggested: company profile or brochure. Word .doc/.docx not accepted yet.

5.4 Business Pin Location

Section title is Business Pin Location (not “Business Location”). Map frame plus “Open in Google Maps” using coordinates when present, otherwise the address string.

5.5 Inquiry and platform buttons

  • Inquiry form stays on the profile sidebar.
  • WhatsApp button only if a number exists → https://wa.me/<digits>.
  • Viber button only if a number exists → viber://chat?number=+<digits>.
  • Website / Facebook / Instagram / LinkedIn only if URLs exist.
  • Do not show empty platform buttons.
Partial / ops. Inquiry submit is captured in the product. A full two-way customer–business message thread UI was not part of this visual revision. Document tracking as an inbox/admin capability, not as a new public screen in this spec.

6. About

6.1 Core Purpose (formerly “Why the platform exists”)

Kicker: CORE PURPOSE. Heading: Why Findra exists.

To create a simpler, more effective way to discover and showcase businesses in the Philippines.

Supporting rows (kept, as requested — they name the problems Findra removes):

  • Too Much Clutter — Endless options, unclear choices.
  • Low Relevance — Wrong matches waste time.
  • Hard to Trust — Incomplete or outdated information.

6.2 Brand values

Kicker BRAND VALUES, title “Guiding principles”. Three cards:

  • No Noise — Clarity over clutter.
  • Structured Discovery — Organized information.
  • Credibility — Complete and trustworthy profiles.

Layout today is the shared InfoCards treatment. Mission/Vision use the image-card + kicker pattern; values can be polished later to match that chrome without changing copy.

6.3 How it works for seekers

  1. Search — Find businesses that match your needs.
  2. Evaluate — Review services and key details to make an informed choice.
  3. Connect — Connect with businesses that match your needs. (Client wording. If a build still says “Connect to”, treat “with” as the approved line.)

6.4 How it works for businesses

  1. Build Your Profile — Add your business, services, and key details.
  2. Discovery — Your business is found by people based on what you offer and what they’re looking for.
  3. Connect — Make it easy for people to get in touch with your business.

6.5 Newsletter

Signup on About posts to /api/newsletter/subscribe with source: "about-page". Show success and error messages in-page. Storage and admin access are operational, not a new public page.

7. Packages

Guest-visible at /packages. No account required to view or to start listing details.

Two Basic cards, side by side:

  • Basic — Regular Pricing
  • Basic — Early Bird Offer (featured). May show remaining slots or Sold out.

Price shown as ₱ / month with “(6 months locked in)”.

Default inclusion points (unless admin overrides features):

  1. Dedicated Business Profile
  2. Secure Business Dashboard
  3. SEO-Optimized Business Page
  4. Built-in Inquiry Form and Direct Contact Tools
  5. Location-Based Search
  6. Relevant Category Listing

Flow: view plan → Create Business Profile / start listing as guest → account or sign-in before PayMongo → listing pending admin review.

States: “Loading packages…” and “Packages are being updated. Please check back shortly.”

8. Contact

  • Remove “How Can We Help?”
  • Remove “Have a question about Findra, your business listing, or how the platform works? Our team is here to help.”
  • Keep intro: Reach out anytime and we’ll get back to you as soon as possible.
  • Form heading: Send a message. Fields: Name*, Email*, Phone (country code + national), Message.
  • Submit POST /api/inquiries → /contact/thank-you.

Messages are stored as inquiries for the team to manage in the product backend — this revision does not add a public ticket portal.

12. QA checklist (walk findra.ph)

  1. Home keyword: type without seeing suggestions; Search opens Businesses with that keyword.
  2. Home category Search and each category tile open Businesses showing only that category.
  3. Featured cards: category is one of the five; descriptions align and truncate evenly.
  4. Be Discovered uses the two-line client sentence.
  5. Footer: white logo, Facebook + Instagram only, no Account Login.
  6. Businesses breadcrumb is Home → Businesses.
  7. With Category All and empty keyword/service, no result list / matching count.
  8. Location input disabled until category, sub-category, service, or keyword is set.
  9. Find a Service filters the grid; no bullet list under it.
  10. Profile Category line includes sub-categories; Operating Hours sits under address; map titled Business Pin Location.
  11. Editor blocks About at 200, services at 3×25, gallery at 6×30-char captions, one video, one attachment.
  12. Gallery photo opens lightbox with caption.
  13. MP4 featured video shows a native player; YouTube still embeds.
  14. WhatsApp/Viber hidden when empty; correct deep links when present.
  15. About Core Purpose sentence and seeker/business steps match this spec.
  16. Packages: two Basic cards, six inclusion bullets, visible logged out.
  17. Contact intro is only the “Reach out anytime…” sentence.

13. Open items (do not treat as shipped design)

  • Full conversation tracking between a business and its customers.
  • Admin newsletter-list runbook / screenshots.
  • Brand values block visually matching Mission/Vision image cards.
  • Seeker Connect line: prefer “Connect with” if any environment still says “Connect to”.
  • Accessibility follow-ups from the Playwright audit (contrast, unnamed selects, duplicate homepage H1 in the accessibility tree, missing alts on category images) are engineering polish, not this client punch list.
